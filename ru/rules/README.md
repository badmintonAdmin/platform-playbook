# Правила платформы

Свод инженерных правил платформы: как строить backend и frontend качественно,
расширяемо и управляемо. Опора — **чистая архитектура** и **DDD**, единый API как
продукт для нескольких клиентов (web, mobile, интеграции).

Правила **переиспользуемы между продуктами**: они описывают, *как строить*, а не
*что за продукт*. Конкретные предметные области, интеграции и доменные доктрины —
отдельный продуктовый слой поверх этих правил.

## Приоритет при конфликте

```
PLATFORM.md  >  BACKEND_RULES.md / FRONTEND_STRUCTURE.md  >  *_STRUCTURE / PRODUCTION
```

Если частное правило противоречит платформенному принципу — **побеждает принцип** (или
частное правило исправляется). Продуктовый слой не может ослаблять платформенные
инварианты безопасности/архитектуры, только ужесточать под свою предметную область.

## Скиллы-спутники

Правила операционализированы скиллами в [.claude/skills/](../.claude/skills/) —
типовые процедуры, которые исполняют свод на практике: `new-domain`, `new-endpoint`,
`new-event`, `new-frontend-section`, `rules-review`, `rules-sync` (карта — в корневом
[CLAUDE.md](../CLAUDE.md)). Изменение правил тянет обновление скиллов — это шаг
`rules-sync`.

## Статус и заметки

- Свод развивается **циклично**: сначала база и чистка, затем углублённые проходы по
  разделам.
- Продуктовые правила и доктрины в этот свод не попадают — их место в `plans/`
  проекта (см. [plans/DECISIONS.md](../plans/DECISIONS.md) и `plans/design/`).

# Новая frontend-секция

Правила: [rules/FRONTEND_STRUCTURE.md](../../../rules/FRONTEND_STRUCTURE.md);
платформенный контракт: [rules/PLATFORM.md](../../../rules/PLATFORM.md) §3–§5.

## Шаг 0 — определить место
- **Какая поверхность?** Пользовательская (`/app`), админская (`/app/admin`), публичная
  (`(marketing)` / `(auth)`). Не смешивать назначения (правило 111): админское — только
  в админскую.
- **Какая route group?** Публичное/защищённое — явно; защищённое покрывает `middleware.ts`.
- Видимость по роли — гейт на фронте только UX; реальную проверку делает backend
  (правило 13).

## Шаг 1 — данные
- Какие эндпоинты нужны? Если их нет — сначала контракт на backend (→ скилл
  `new-endpoint`), фронт не выдумывает форму данных.
- Типы — **из сгенерированных OpenAPI-типов** (правило 6), руками DTO не писать.
- Все вызовы — через единый `apiFetch` (правило 104): никаких голых `fetch`, никаких
  хардкод-URL (правило 14).
- Серверное состояние — в выбранном механизме проекта (RSC-fetch / query-библиотека);
  не копировать ответы API в глобальный стор (правило 106).

## Шаг 2 — компоненты
- Страница **тонкая**: композиция компонентов (правило 108).
- Серверный компонент по умолчанию; `"use client"` — только на интерактивных листьях
  (правило 105).
- Переиспользуемые примитивы → `components/ui/` (без предметной области);
  специфика секции → папка её поверхности (правило 110).

## Шаг 3 — состояния и ошибки
- Обязательные состояния: загрузка, пусто, ошибка, успех. Ошибки — из единого конверта:
  показать `message`, ветвиться по коду `error` (правило 9).
- Формы: клиентская валидация для UX + маппинг серверных ошибок полей из `details`
  (правило 113).
- Нет данных/метрики не заинструментированы → показывать «Pending», не выдумывать
  (правило 114).
- Секреты в UI — write-only: маскировать, пустое поле сохраняет прежнее значение
  (правило 85).

## Шаг 4 — a11y (гейт, правило 115)
- Семантический HTML, labels у полей, клавиатурная навигация, видимый фокус, контраст.

## Верификация
- [ ] Нет голых `fetch`/хардкод-URL/ручных DTO
- [ ] Клиентская граница минимальна; страница тонкая
- [ ] Все 4 состояния UI; ошибки по коду конверта
- [ ] Сверить по разделу «Frontend» из
      [rules/RULES_CHECKLIST.md](../../../rules/RULES_CHECKLIST.md)

# Аудит по правилам платформы

Источник истины: [rules/RULES_CHECKLIST.md](../../../rules/RULES_CHECKLIST.md) (128
правил). При спорной трактовке строки чек-листа — открыть полный документ
(PLATFORM / BACKEND_RULES / BACKEND_STRUCTURE / PRODUCTION / FRONTEND_STRUCTURE),
он приоритетнее.

Это **аудит соответствия правилам**, не общий поиск багов. Не подменять его
код-ревью: логические ошибки отмечать отдельной секцией «вне чек-листа», кратко.

## Шаг 1 — определить объём
- Без аргументов — текущий дифф (`git diff` + staged; если пусто — последний коммит).
- Указан PR/ветка/файлы — взять их.
- Перечислить затронутые области: backend-домены, core, миграции, события, фронт.

## Шаг 2 — отобрать применимые разделы
Не гонять все 128 правил по каждому файлу — взять релевантные разделы:

| В диффе | Разделы чек-листа |
|---|---|
| `apps/*` (backend) | Слои (17–32), DI (33–39), Домены (40–50), Ошибки (66–69), Безопасность (80–88) |
| `models` / `migrations` | Модели БД (51–61), Миграции (62–65) |
| `events.py` / консьюмеры / джобы | События (70–76), Фоновая работа (77–79) |
| роутеры / схемы (контракт) | Платформа/API (1–16) |
| frontend | Frontend (103–115), Платформа/API (5–11, 14) |
| инфраструктура / CI / Docker | Эксплуатация (89–97), Безопасность (86–87), Тесты (98–102) |
| ветки / PR / релиз / деплой | Git и доставка (116–128) |

## Шаг 3 — проверить и вынести вердикт
Для каждого кандидата на нарушение — **подтвердить по коду** (прочитать контекст, не
судить по одной строке диффа). Ложные срабатывания отбрасывать.

## Шаг 4 — отчёт
Формат — по убыванию серьёзности:

```
## Нарушения
- **№25** (ORM выше репозитория) — `apps/orders/services.py:42`:
  сервис возвращает модель Order. Фикс: вернуть OrderReadSchema.

## Спорное / на усмотрение
- №30 … (почему спорно)

## Соответствует
Проверены разделы: Слои, DI, Модели БД — нарушений нет.
```

- Нарушение = номер + суть + `file:line` + короткий фикс.
- Ничего не чинить без запроса; предложить `--fix`-проход отдельно.
- Если диффа нет и объём не указан — спросить, что проверять, а не сканировать весь репозиторий.

# Синхронизация свода правил

Свод: `rules/` — полные документы + [RULES_CHECKLIST.md](../../../rules/RULES_CHECKLIST.md)
(выжимка) + [README.md](../../../rules/README.md) (индекс). Инвариант: **чек-лист — это
проекция полных документов**; расхождение = баг документации.

## Когда добавляется/меняется правило
1. **Сначала полный документ** (PLATFORM / BACKEND_RULES / BACKEND_STRUCTURE /
   PRODUCTION / FRONTEND_STRUCTURE) — правило с обоснованием («почему»), в правильном
   разделе, по иерархии (платформенное — в PLATFORM, не дублировать вниз).
2. **Затем чек-лист** — одна строка на правило, в соответствующий раздел.
   Перенумеровка допустима (ссылки на номера живут только внутри репо — обновить их:
   `grep -rn "правил" .claude/skills/ rules/` по затронутым номерам).
3. **README** — обновить количество правил в описании чек-листа; новый документ —
   добавить в карту и порядок чтения.
4. **Скиллы** — если правило меняет процедуру (новый шаг, новая проверка) — обновить
   соответствующий скилл в `.claude/skills/`.

## Проверки консистентности (прогонять всегда)
- [ ] Каждое правило чек-листа имеет источник в полном документе (и наоборот — новые
      «жёсткие» правила документов отражены в чек-листе).
- [ ] Нумерация сквозная без пропусков; количество в README совпадает.
- [ ] Кросс-ссылки вида «§N» и «правило N» указывают на существующие разделы
      (при вставке разделов в середину документа номера съезжают — проверить).
- [ ] Нет противоречий между документами: при конфликте побеждает верхний по иерархии
      (README → «Приоритет при конфликте»); противоречие — чинить, не оставлять.
- [ ] Ссылки между файлами (`[…](FILE.md)`) не битые.

## Коммит
`docs(rules): <что изменилось>` — Conventional Commits; правки правил и синхронизация
чек-листа — в одном коммите, чтобы история не содержала рассинхронизированных состояний.
